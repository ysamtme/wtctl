# Код на сервере, функции библиотек, фоновые задачи

Право `execute` требуют `hcm_script` и вызов функции (`rpc.call`). Список функций и их код (`rpc.list`, `rpc.describe`) читаются без него. Код и функции могут менять данные, отката нет.

## `hcm_script`

Код выполняется на сервере от имени пользователя подключения. Ответ — то, что код присвоил переменной `RESULT`. Это должен быть массив.

```javascript
var rows = XQuery("for $e in collaborators where $e/is_dismiss = false() return $e");
RESULT = [];
for (row in rows) RESULT.push({ id: row.id + '', name: row.fullname + '' });
```

Ответ: `{"result":[{"id":"6148914691236517121","name":"Иванов Иван Иванович"}], "executionId":"hcm_inline_…"}`.

Открыть документ, изменить и сохранить:

```javascript
var doc = OpenDoc(UrlFromDocID(Int('0x65CCCE16EC975831')));
doc.TopElem.comment = 'из кода';
doc.Save();
RESULT = [{ id: doc.DocID + '', comment: doc.TopElem.comment + '' }];
```

Значения передавай в код аргументом `params`, а не подстановкой в текст: в коде это готовая переменная `PARAMS`.

```json
{ "code": "var doc = OpenDoc(UrlFromDocID(Int(PARAMS.id))); RESULT = [doc.TopElem.name + ''];", "params": { "id": "0x65CCCE16EC975831" } }
```

- `params` — объект JSON любой вложенности. Строки, числа, `true`, `false`, `null`, списки и объекты приходят как есть; кавычки и обратный слэш в строках экранировать не нужно.
- ID передавай строкой и превращай в число в коде: `Int(PARAMS.id)`.
- Код из файла на этом компьютере выполняет `file` вместо `code`: `hcm_script {file:"C:\\work\\check.js", params:{…}}`. Путь полный.

Что возвращать в `RESULT`:

- строки, числа, логические значения, `null`, массивы и простые объекты `{…}`;
- числа и логические значения приходят строками: `2` → `"2"`, `true` → `"1"`;
- значение, полученное через `String(x)`, в ответ не попадает — пиши `x + ''`;
- дату возвращай строкой: `StrDate(d)` даёт `"01.10.2026 23:08:29"`, `StrXmlDate(d)` — `"2026-10-01T23:08:29+00:00"`. Сама дата на части версий сервера в ответ не попадает;
- документ и его структуру напрямую вернуть нельзя: структура даёт `SCRIPT_RESPONSE`, а сам документ на части версий сервера молча пропадает из ответа. Возвращай отдельные поля или текст XML: `doc.TopElem.access.Xml`;
- ID из кода приходит в десятичной записи. Его можно передавать в другие инструменты как есть.

Язык — SP-XML Script, не современный JavaScript:

- только `var`; `let`, `const` и стрелочных функций нет;
- перебор: `for (row in rows)`;
- ID из строки `0x…`: `Int('0x5555555555555501')`;
- обратный слэш в строке удваивают: `'B:\\dir'`. В тексте JSON, который код разбирает через `ParseJson`, его удваивают ещё раз: `ParseJson('{"w":"B:\\\\dir"}')`. Одиночный `\` перед обычной буквой молча пропадает — и в строке кода, и в `ParseJson`: `'B:\dir'` даёт `B:dir`. Проще собрать объект прямо в коде;
- `curUserID` — пользователь подключения. Запроса портала в этом коде нет: `Request` и `Response` не используй.

Функции платформы и остальные правила языка гайд не описывает: для нетривиального кода нужна документация по платформе.

Ошибки кода приходят с кодом `SCRIPT_FAILED`, текст — в `error.details.scriptError`:

| `scriptError` | Причина |
| --- | --- |
| `let not defined` | в коде `let` или `const` |
| `JavaScript syntax error.` | синтаксис: стрелочная функция, незакрытая скобка |
| `no_such_var not defined` | имя не объявлено |
| `Элемент не найден … OpenDoc()`, `Object wt_data … not found` | документа с таким ID нет |
| `Result is not an array` | `RESULT` присвоен не массив |

`SCRIPT_RESPONSE` с текстом «RESULT — не массив» значит, что код не присвоил `RESULT`.

Запрос к базе из кода, `XQuery("sql: …")`, об ошибке не сообщает: при ошибке в тексте SQL (опечатка, колонка, которой нет) он возвращает пустую выборку, исключения нет, `try/catch` не срабатывает. Код при этом отвечает `ok: true` и пустым `result`. Пустой ответ такого запроса проверяй отдельно: причину база пишет в лог `spxml_unibridge`, см. [logs.md](logs.md).

Длинный текст ошибки приходит до 2000 знаков; обрезанный кончается знаком «…». Целиком он записан в логе `xhttp` рядом с `executionId` из ответа.

Отладочную строку из кода пишет `alert('текст')`: она попадает в лог `xhttp`, см. [logs.md](logs.md).

Если код упал, часть изменений могла пройти. Проверь данные, прежде чем запускать его снова.

## Функции библиотек

Сервер разрешает вызывать снаружи часть функций своих библиотек (около 250 из тысячи с лишним). Остальные функции вызывают из кода: `hcm_script` с `tools.имя_функции(…)`.

1. Найти: `hcm_api_read {operationId:"rpc.list", args:{query:"version"}}`. Фильтры: `library`, `method`, `query` (одна подстрока имени функции или имени параметра; описаний у функций нет — ищи английским словом, которым платформа называет нужное в именах). С `all:true` в списке будут и функции только для кода на сервере — у них `serverOnly:true`. Без `all` ответ называет, сколько таких функций подошло под фильтр и не показано: `serverOnlyHidden`.
2. Посмотреть параметры и код: `hcm_api_read {operationId:"rpc.describe", args:{targetId:"tools.get_version", source:true}}`. Работает для любой функции библиотеки; у функции только для кода на сервере в ответе `serverOnly:true`. У параметров известны только имена: типы и что функция возвращает, видно по коду.
3. Вызвать: `hcm_api_execute {operationId:"rpc.call", args:{library:"tools", method:"get_version", arguments:["wtv"]}}`. Ответ: `{"value":"2025.2.1535"}`.

Аргументы идут по порядку параметров. Строки, логические значения, `null` и целые числа передаются как есть. Для остального укажи тип явно: `{"valueType":"date","lexicalValue":"2026-10-01T00:00:00"}`, для большого целого — `{"valueType":"integer","lexicalValue":"6148914691236517121"}`.

Список функций не говорит, меняет ли функция данные. Читай её код через `source:true`.

Отказ в вызове клиент объясняет по списку функций сервера:

| Код | Что значит |
| --- | --- |
| `UNKNOWN_RPC_TARGET` | такой функции или библиотеки нет; в `hint` — похожие имена |
| `RPC_SERVER_ONLY` | функция есть, но с клиента не вызывается, сервер ничего не выполнил: вызови её из кода — `hcm_script` с `RESULT = [tools.имя_функции(…) + ''];`, массив из её ответа обойди циклом, из объекта возьми нужные поля |
| `INVALID_RPC_ARGUMENT` | аргумент задан не так; в `message` — его номер в `arguments` |
| `PLATFORM_SOAP-FAULT` | функция вызвана, отказ случился внутри неё или из-за значений аргументов |

## Агенты сервера

Запустить агента и дождаться конца его кода: `hcm_api_execute {operationId:"agents.run", args:{id:"0x65D6BB73BFE67019"}}`.

```json
{ "started": true, "startedAt": "2026-10-09T20:31:17", "finishedAt": "2026-10-09T20:31:19" }
```

- ID агента находит `hcm_query {catalog:"server_agents", where:{code:"…"}, fields:["id","name"]}`.
- `objectId` в коде агента — `OBJECT_ID`, список `objectIds` — `OBJECTS_ID_STR`. Параметры агента берутся из его документа.
- Ошибку в коде агента ответ не показывает: `started:true` значит только, что код запущен и закончился. Что он написал, ищи в логах за время между `startedAt` и `finishedAt`: строки `Starting server agent` и `Finished server agent` — в логе `agent`, `alert` и текст ошибки — в `xhttp`. У строк одного запуска одна метка потока в квадратных скобках: `hcm_logs_search {file:"xhttp_….log", context:"0139"}`.
- Вызов ждёт не дольше времени ожидания подключения (`timeoutMs`). Долгого агента запускай без ожидания — `rpc.call {library:"tools", method:"start_agent", arguments:["0x…"]}` — и следи за логом `agent` через `hcm_logs_follow`.
- Как и запуск из админки, вызов сохраняет в агенте дату последнего запуска.

## Фоновые задачи

Долгую функцию запускают задачей:

1. `hcm_api_execute {operationId:"rpc.call", args:{library:"tools", method:"get_version", arguments:["wtv"], async:true}}` → `{"TrackingID":"0x113AE554167EEE65"}`.
2. `hcm_api_read {operationId:"web.spxml.getAsyncMethodStatus", args:{trackingId:"0x113AE554167EEE65"}}` → пока задача идёт, `IsRunning:"1"`; когда закончилась — `{"IsRunning":"0","value":"2025.2.1535"}`: `value` такой же, как у обычного вызова. Если функция упала, вместо `value` приходит `ErrorText`.

Итог сервер отдаёт один раз: после ответа с `IsRunning:"0"` запись о задаче удаляется. Сохрани ответ и больше эту задачу не опрашивай.

Остановить задачу: `hcm_api_write {operationId:"web.spxml.killAsyncMethod", args:{trackingId:"…"}}`. Это просьба: уже сделанные изменения не откатываются.

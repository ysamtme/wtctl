# wtctl

[![npm](https://img.shields.io/npm/v/wtctl)](https://www.npmjs.com/package/wtctl)
[![license](https://img.shields.io/npm/l/wtctl)](LICENSE)

Клиент административных API сервера WebSoft HCM (WebTutor): CLI, SDK и MCP-сервер поверх одного ядра. Работает с каталогами, объектами, формами, файлами, логами, агентами сервера и кодом SP-XML.

На сервер ничего ставить не нужно: клиент использует те же вызовы, что и штатная админка, без своих обработчиков, шаблонов и библиотек.

> **Неофициальный проект (альфа-версия).** Компания WebSoft его не разрабатывает, не одобряет и не поддерживает; названия WebSoft HCM и WebTutor используются в проекте только для указания совместимости. Использование на свой риск: [права и риски](#права-и-риски), [состояние проекта](#состояние-проекта).

## Возможности

- **Каталоги и поиск** — фильтрация по условиям в JSON (без ручного XQuery), постраничное чтение и сглаживание различий между MS SQL и PostgreSQL; сырые запросы XQuery тоже поддерживаются.
- **Объекты и документы** — чтение (включая полный XML), создание, удаление и точечная правка по полям с сохранением остальных узлов документа, предпросмотром изменений, защитой от перезаписи чужих правок и сверкой после сохранения.
- **Формы** — просмотр типов объектов и их полей, в том числе настраиваемых.
- **Код и серверные задачи** — выполнение кода на SP-XML, вызов функций библиотек, запуск агентов сервера и управление фоновыми задачами.
- **Файлы, логи и сведения о сервере** — чтение, запись и удаление файлов, разбор логов на отдельные события и отслеживание новых записей, информация о версии сервера и базе данных.
- **Права и контроль записи** — новые подключения работают только на чтение (запись и выполнение кода включаются отдельно); для каждой записи возвращается явный исход (запрос не отправлен, подтверждён или исход не определён) без автоматических повторов при сбое.
- **Диагностика и большие ответы** — ошибки с кодом, причиной, подсказкой по-русски и похожими именами при опечатке; сохранение объёмных ответов локально для чтения по частям; встроенный гайд по работе с клиентом.

Всего доступно 55 операций: основные вынесены в отдельные команды CLI, методы SDK и инструменты MCP, остальные вызываются по ID.

## Интерфейсы и сценарии

У `wtctl` одно ядро с общим набором операций, аргументами, форматом ответов и проверкой прав, и три интерфейса поверх него:

- **CLI `wtctl`** — для разовых вызовов из терминала, скриптов и задач по расписанию;
- **SDK** — для своего кода, утилит и автотестов на JavaScript и TypeScript;
- **MCP-сервер** — для подключения к LLM-агентам в Claude Code, Codex, opencode и других приложениях с поддержкой MCP (в Claude Code и Codex ставится плагином вместе с навыком).

Типовые сценарии:

- **Отладка кода на сервере** — проверка полей и данных, запуск SP-XML, чтение ошибок в логах и повторные прогоны.
- **Подготовка тестовых данных** — создание нужных объектов перед проверкой и их удаление после.
- **Автотесты на SDK и CLI** — скрипты, которые готовят данные, запускают проверяемый код и сверяют состояние объектов и логи.
- **Разбор сбоев** — воспроизведение проблемы, поиск по логам и сопоставление с объектами и кодом на сервере.
- **Массовые правки** — выборка объектов по условиям, предпросмотр изменений, пакетное обновление и проверка результата.
- **Выгрузки и сверки** — сбор данных, для которых в админке нет готового отчёта.

Вызовы из терминала:

```shell
npx -y wtctl types --search сотрудник
npx -y wtctl schema collaborator --origin custom
npx -y wtctl query --catalog collaborators --fields id,fullname --limit 5
```

CLI отвечает в JSON: `{"ok":true,"data":…}` или `{"ok":false,"error":{"code","message","hint"}}`. Если установить пакет глобально (`npm install -g wtctl`), команды пишутся без `npx -y`.

Из кода на JavaScript или TypeScript:

```javascript
import { loadConfig, withHcmClient, unwrap } from "wtctl";

await withHcmClient(loadConfig(), async (client) => {
  const page = unwrap(
    await client.query({
      catalog: "collaborators",
      where: { is_dismiss: false },
      fields: ["id", "fullname"],
      limit: 5,
    }),
  );
  for (const row of page.items) console.log(row.id, row.fullname);
});
```

Примеры простых запросов через MCP-сервер:

| Запрос | Инструменты MCP |
| --- | --- |
| «Какие настраиваемые поля есть у сотрудника?» | `hcm_schema` |
| «Найди работающих сотрудников без e-mail, покажи ФИО и подразделение» | `hcm_types` и `hcm_schema` — уточнить каталог и поля, затем `hcm_query` |
| «Переименуй группу `sales` в „Отдел продаж“. Сначала покажи, что изменится» | `hcm_query`, затем `hcm_object_patch` (сначала с `preview`, потом без) |
| «Запусти агента сервера `my_import` и покажи, что он написал в лог» | `hcm_api_execute` (`agents.run`), затем `hcm_logs_search` |
| «Найди в логах, почему сервер отказал при сохранении карточки» | `hcm_logs_follow` по логу `xhttp` за сегодня |

## Быстрый старт

Потребуются Node.js 22.16 или новее, учётная запись с доступом в админку сервера HCM и git (если планируется ставить плагин в Claude Code или Codex).

1. **Настройка подключения.** Команда спросит адрес сервера, логин и пароль:

   ```shell
   npx -y wtctl config init
   ```

   Конфигурация сохраняется в `~/.wtctl/connections.json`, её используют CLI, SDK и MCP-сервер. Новое подключение создаётся только с правом на чтение.

2. **Проверка подключения.** Команда последовательно проверит вход, версию сервера, тестовый запрос и чтение документа:

   ```shell
   npx -y wtctl check
   ```

   Если какой-то шаг не пройдёт, в ответе будет причина. После успешной проверки CLI и SDK уже готовы к работе.

3. **Подключение плагина (для Claude Code и Codex).** Плагин устанавливает сразу MCP-сервер и навык.

   Claude Code:

   ```shell
   claude plugin marketplace add ysamtme/wtctl
   claude plugin install wtctl@wtctl
   ```

   Codex:

   ```shell
   codex plugin marketplace add ysamtme/wtctl
   codex plugin add wtctl@wtctl
   ```

   Для проверки работы MCP-сервера достаточно вызвать инструмент `hcm_status` — в ответе должны прийти версия сервера HCM и права текущего подключения.

Настройка других приложений (включая opencode), установка без плагина, подключение без файла конфигурации, обновление, удаление и разбор неполадок описаны в [docs/installation.md](docs/installation.md).

## Права и риски

Подключать `wtctl` к боевому серверу не стоит: проект в альфа-версии, и ошибиться может как агент, так и сам клиент. Если запись или выполнение кода разрешены, клиент не помешает агенту изменить не тот объект или выполнить на сервере ошибочный код.

На сервере для агента нет отдельной роли — клиент авторизуется под учётной записью из файла подключений и выполняет запросы от её имени и с её правами. На стороне клиента эти права можно только сузить: по умолчанию включено только чтение, а запись (`write`) и выполнение кода (`execute`) разрешаются отдельно в [настройках прав](docs/configuration.md#права).

Подробнее о правах, хранении паролей и диагностике сбоев записи — в [docs/security.md](docs/security.md).

## Совместимость

| | Проверено | Не проверено |
| --- | --- | --- |
| Версия сервера | 2025.1.1171, 2025.1.1333, 2025.2.1470, 2025.2.1535 | другие версии, в том числе старше 2025.1 |
| Сервер | Windows | Linux |
| База данных | MS SQL, PostgreSQL; на файловой базе — самопроверка, файлы и код на сервере (2025.2.1535) | остальное на файловой базе |
| Адрес и вход | `http://`, логин и пароль учётной записи с доступом в админку | `https://`, reverse proxy, вход через SSO |
| Клиент | Windows, Node.js 24 | Linux, macOS |
| Приложения (харнессы) | Claude Code, Codex, opencode ([с выключенным Code Mode](docs/installation.md#opencode)); в Antigravity — установка плагина и подключение MCP-сервера | Cursor, VS Code с Copilot, Copilot CLI и другие приложения с поддержкой MCP |

Работа на крупных базах (каталоги на сотни тысяч записей, длинные очереди фоновых задач) пока не проверялась. Если что-то из непроверенного окружения не заработает, `wtctl check` покажет, на каком шаге возникает проблема.

Детали по отличиям между версиями и базами, а также известные ограничения — в [docs/compatibility.md](docs/compatibility.md). Про отличия поиска на MS SQL и PostgreSQL отдельно написано в [гайде по запросам](skills/wtctl/references/queries.md).

## Состояние проекта

Проект находится в альфа-версии:

- **Недокументированный API.** Клиент опирается на внутренние вызовы админки, которые WebSoft может изменить в любом обновлении сервера.
- **Изменения до 1.0.** Имена инструментов, команд и аргументов ещё могут меняться — все несовместимые изменения фиксируются в [CHANGELOG](CHANGELOG.md).
- **Разработка с LLM.** Код пишется LLM-агентами без построчного ручного ревью; качество контролируется автотестами и прогонами на серверах из [таблицы совместимости](#совместимость). Проект развивается именно в таком формате.
- **Модели и контекст.** Клиент в основном проверялся на сильных моделях и в связке с дополнительными непубличными инструментами (документацией по платформе для агента и линтером SP-XML). В изоляции и на более слабых моделях он тестировался мало; адаптация под такие сценарии в планах, но без конкретных сроков.
- **Обратная связь.** Об ошибках и идеях можно написать в [issues](https://github.com/ysamtme/wtctl/issues) — что лучше приложить к описанию, указано в [CONTRIBUTING](CONTRIBUTING.md). Оперативная поддержка и доработки по запросам не гарантируются, но возможны.

## Разработка

```shell
npm ci
npm run build
node dist/cli/bin.js version
```

`npm run build` собирает CLI (`dist/cli/bin.js`) и SDK в `dist/` со встроенными зависимостями. Все проверки запускаются командой `npm run verify`. Архитектура клиента описана в [docs/architecture.md](docs/architecture.md).

Собранный плагин публикуется в ветке `plugin`. Для локальной проверки в Claude Code его можно подключить из папки с исходниками на один сеанс: `claude --plugin-dir .`.

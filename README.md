# wtctl

[![npm](https://img.shields.io/npm/v/wtctl)](https://www.npmjs.com/package/wtctl)
[![license](https://img.shields.io/npm/l/wtctl)](LICENSE)

`wtctl` — клиент сервера WebSoft HCM (WebTutor) для LLM-агентов и скриптов: MCP-сервер, CLI и SDK. Работает через API админки. На сервер ничего ставить не нужно: ни обработчиков, ни шаблонов, ни библиотек.

_Unofficial client for WebSoft HCM (WebTutor) servers: an MCP server, a CLI and an SDK that work through the admin API. The documentation is in Russian._

> **Неофициальный проект.** Компания WebSoft его не разрабатывает, не одобряет и не поддерживает. «WebSoft HCM» и «WebTutor» — обозначения их правообладателя. Здесь они только указывают, с каким сервером работает клиент.
>
> **Альфа-версия.** Использование — на свой риск: [права и риски](#права-и-риски), [состояние проекта](#состояние-проекта).

## Что умеет

Что покрыто из API админки:

- каталоги и документы объектов: поиск, чтение, создание, правка, удаление;
- формы: типы объектов и их поля, включая настраиваемые;
- выполнение кода, запросы XQuery, функции библиотек, агенты сервера, фоновые задачи;
- логи, файлы, документы как XML, сведения о сервере;
- остальные операции вызываются по ID, всего их больше ста.

Что добавлено поверх API:

- условия поиска в JSON вместо XQuery и чтение страницами; различия MS SQL и PostgreSQL учтены в клиенте или описаны в гайде;
- правка по путям полей: предпросмотр, защита от чужой правки, сверка после записи; остальное в документе не трогается;
- три исхода записи: не отправлено, подтверждено, не определён; сама запись не повторяется;
- права подключения: по умолчанию только чтение;
- ошибки с кодом, причиной и подсказкой по-русски, похожие имена при опечатке;
- большие ответы сохраняются локально и читаются частями;
- логи разбираются на события, за логом можно следить;
- гайд для агента встроен в MCP-сервер и CLI.

## Как используется

Основной способ работы — агентный: агент получает задачу словами и сам доводит её до результата.

У трёх интерфейсов одно ядро: одни и те же операции, аргументы, ответы и проверка прав. MCP-сервер — для агента в чате. CLI и SDK дают то же самое без чата: в скриптах, автотестах, задачах по расписанию и в своих программах.

| Интерфейс | Для чего |
| --- | --- |
| MCP-сервер | Для агента в Claude Code, Codex и других приложениях с поддержкой MCP. В Claude Code и Codex ставится плагином, вместе с навыком (skill). |
| CLI `wtctl` | Для скриптов и разовых вызовов из терминала. |
| SDK | Для своего кода на JavaScript и TypeScript. |

На что это рассчитано:

- реализовать задачу целиком: разобраться, как устроены данные на этом сервере, написать код на SP-XML, выполнить его, прочитать ошибку в логе, исправить и повторить;
- подготовить тестовые данные: создать объекты для проверки и убрать их после неё;
- написать автотесты на SDK или CLI: скрипт создаёт данные, запускает проверяемый код и сверяет результат на сервере и в логах;
- найти причину ошибки: воспроизвести, прочитать логи, сопоставить с кодом и данными;
- изменить много объектов: найти, показать план, выполнить скриптом, проверить каждый;
- собрать выгрузку или сверку, для которой в админке нет готового отчёта.

Простейшие запросы к агенту, на один-два вызова:

| Запрос | Что вызывает агент |
| --- | --- |
| «Какие настраиваемые поля есть у сотрудника?» | `hcm_schema` |
| «Найди работающих сотрудников без e-mail, покажи ФИО и подразделение» | `hcm_types` и `hcm_schema` — узнать каталог и поля, `hcm_query` — найти |
| «Переименуй группу `sales` в „Отдел продаж“. Сначала покажи, что изменится» | `hcm_query`, затем `hcm_object_patch`: сначала с `preview`, потом без |
| «Запусти агента сервера `my_import` и покажи, что он написал в лог» | `hcm_api_execute` с операцией `agents.run`, затем `hcm_logs_search` |
| «Найди в логах, почему сервер отказал при сохранении карточки» | `hcm_log_follow` по логу `xhttp` за сегодня |

То же из терминала:

```shell
npx -y wtctl types --search сотрудник
npx -y wtctl schema collaborator --origin custom
npx -y wtctl query --catalog collaborators --fields id,fullname --limit 5
```

CLI отвечает JSON: `{"ok":true,"data":…}` или `{"ok":false,"error":{"code","message","hint"}}`. После `npm install -g wtctl` те же команды пишутся без `npx -y`.

И из своего кода:

```javascript
import { loadConfig, withHcmClient, unwrap } from "wtctl";

await withHcmClient(loadConfig(), async (client) => {
  const page = unwrap(
    await client.query({ catalog: "collaborators", where: { is_dismiss: false }, fields: ["id", "fullname"], limit: 5 }),
  );
  for (const row of page.items) console.log(row.id, row.fullname);
});
```

## Быстрый старт

Что нужно:

- Node.js 22.16 или новее;
- git: через него Claude Code и Codex скачивают плагин;
- учётная запись, которую сервер HCM пускает в админку.

1. Создать подключение. Команда спросит адрес сервера, логин и пароль.

   ```shell
   npx -y wtctl config init
   ```

   Подключение сохраняется в `~/.wtctl/connections.json`, его читают все приложения на компьютере. Новое подключение умеет только читать.

2. Проверить подключение.

   ```shell
   npx -y wtctl check
   ```

   Команда идёт по шагам: вход, версия, запрос, чтение документа и так далее. Если шаг не прошёл, в ответе будет причина.

3. Поставить плагин в Claude Code или Codex. В плагине MCP-сервер и навык.

   Claude Code:

   ```shell
   claude plugin marketplace add ysamtme/wtctl
   claude plugin install wtctl@wtctl
   ```

   Codex:

   ```shell
   codex plugin marketplace add ysamtme/wtctl
   codex plugin add wtctl@wtctl
   ```

4. В новом чате попросить агента вызвать `hcm_status`. В ответе должны быть версия сервера HCM и права подключения.

Другие приложения, установка без плагина, подключение без файла, обновление, удаление и разбор неполадок — в [docs/installation.md](docs/installation.md).

## Права и риски

Проект в альфа-версии. Подключать его к боевому серверу — тому, где настоящие данные и работают люди, — крайне не рекомендуется: ошибиться может и агент, и сам клиент. Агент может поменять или удалить не тот объект, выполнить на сервере не тот код. Если запись разрешена, клиент от этого не защитит.

Клиент входит на сервер под учётной записью из файла подключений и делает те же вызовы, что и админка. Отдельного пользователя «агент» для сервера нет: всё, что делает агент, сервер считает действиями этой учётной записи, с её правами.

Клиент может эти права только сузить. Новое подключение умеет только читать. Запись и выполнение кода на сервере включаются отдельно: [права](docs/configuration.md#права).

Лицензия — MIT: программа даётся «как есть», без каких-либо гарантий. Автор не отвечает за потерю или порчу данных, простой сервера и любые другие последствия её использования.

Подробнее о правах, паролях и о том, как понять, прошла ли запись, — в [docs/security.md](docs/security.md).

## Совместимость

| | Проверено | Не проверено |
| --- | --- | --- |
| Версия сервера | 2025.1.1171, 2025.1.1333, 2025.2.1470, 2025.2.1535 | другие версии, в том числе старше 2025.1 |
| Сервер | под Windows | под Linux |
| База данных | MS SQL, PostgreSQL | файловая база |
| Адрес и вход | `http://`, логин и пароль учётной записи с доступом в админку | `https://`, reverse proxy, вход через SSO |
| Клиент | Windows, Node.js 24 | Linux, macOS |
| Приложения (харнессы) | Claude Code, Codex | Cursor, VS Code с Copilot, Copilot CLI, Gemini CLI и другие приложения с поддержкой MCP |
| Объём данных | — | каталоги на сотни тысяч записей, длинные очереди фоновых задач |

Каждый пример вызова из документации и гайда выполнен на этих серверах на обеих базах. Чем поиск на MS SQL отличается от поиска на PostgreSQL, написано в [гайде по запросам](skills/wtctl/references/queries.md).

Если что-то из непроверенного не работает, `wtctl check` покажет, на каком шаге проблема.

## Состояние проекта

Альфа-версия.

- **API сервера.** Клиент делает те же вызовы, что и админка. WebSoft не описывает их как открытый API и может поменять в любом обновлении сервера.
- **Версии клиента.** До версии 1.0 имена инструментов, команд и аргументов могут меняться. Все такие изменения перечислены в [CHANGELOG](CHANGELOG.md).
- **На что рассчитан.** Проект в основном делается под сильные модели и под работу вместе с двумя непубличными инструментами автора: документацией по платформе для агента и линтером кода. На моделях слабее и отдельно от этих инструментов он проверялся мало. Доработки в эту сторону возможны и планируются, сроков нет.
- **Поддержка.** Об ошибках и пожеланиях можно написать в [issues](https://github.com/ysamtme/wtctl/issues); что приложить к сообщению, сказано в [CONTRIBUTING](CONTRIBUTING.md). Активной поддержки и доработок по запросу автор не обещает, но они возможны.

## Разработка

```shell
npm ci
npm run build
node dist/cli/bin.js version
```

`npm run build` собирает CLI в один файл `dist/cli/bin.js` без внешних зависимостей, `npm run verify` запускает все проверки. Как устроен клиент, написано в [docs/architecture.md](docs/architecture.md).

Собранный плагин лежит в ветке `plugin`. Плагин из папки с исходниками Claude Code загружает на один сеанс: `claude --plugin-dir .`.

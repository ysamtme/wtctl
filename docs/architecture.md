# Как устроен клиент

Страница для тех, кто меняет сам клиент.

## Слои

```text
SDK (HcmClient)     CLI wtctl     MCP-сервер
        \              |              /
         HcmRuntime.call(id, args)
                       |
  проверка аргументов → права → операция → ответ или сохранённый результат
                       |
        вызовы протокола сервера (src/native, src/protocol)
                       |
                 сервер WebSoft HCM
```

SDK, CLI и MCP-сервер вызывают одну и ту же функцию `HcmRuntime.call` с ID операции и аргументами. Каждый из них только разбирает свой ввод и показывает ответ. Запросов к серверу, проверки прав и логики операций в них нет, поэтому поведение у них одинаковое.

## Модули

| Модуль | За что отвечает |
| --- | --- |
| `src/protocol/` | HTTP, сессии, SOAP, XML, вложения, WebSocket |
| `src/native/` | вызовы API сервера по одному: описание, проверка аргументов, сессии; право каждой операции объявлено строкой в `src/native/metadata.ts` |
| `src/operation.ts`, `src/operations/` | определение операции одним объектом: ID, эффект и правило эффекта по аргументам, описание, схема аргументов, правила ответа, обработчик; файл на семейство операций |
| `src/operations.ts`, `src/catalog.ts` | реестр: порядок семейств и поиск по ID; список и описание без подключения |
| `src/operation-map.ts` | оглавление операций по темам для `api list` и `hcm_api_list`: темы, заголовки, порядок; строка об операции берётся из её определения |
| `src/runtime.ts` | конвейер вызова: очередь, проверка аргументов, права, обработчик операции, упаковка ответа |
| `src/hcm-server.ts` | единственный путь к серверу: через него идёт каждый запрос, и он же отмечает, что запрос на запись мог уйти |
| `src/write-outcome.ts` | исход записи: не отправлено, подтверждено, не определён |
| `src/reply.ts` | общий вид ответа: предел размера, сохранение целиком, текст ошибки без пароля и путей сервера |
| `src/query.ts` | условия поиска, страницы |
| `src/objects.ts`, `src/documents.ts`, `src/verification.ts` | объекты: чтение, создание, правка XML документа, удаление, сверка после записи |
| `src/schema.ts` | типы объектов и поля из форм сервера |
| `src/scripts.ts`, `src/rpc-catalog.ts` | выполнение кода, функции библиотек |
| `src/server-value.ts` | значение с типом для функций библиотек: кодирование аргумента, разбор ответа |
| `src/logs.ts`, `src/log-output.ts` | логи: чтение, события, слежение, размер ответа |
| `src/files.ts`, `src/server-info.ts`, `src/self-check.ts` | файлы, сведения о сервере, проверка подключения |
| `src/results.ts` | локальное хранение больших ответов и чтение частями |
| `src/sdk.ts`, `src/cli/`, `src/mcp/` | SDK, CLI и MCP-сервер |
| `src/guide.ts`, `src/guide-texts.ts` | гайд для `hcm_guide` и `wtctl guide`; тексты генерирует `npm run generate` из навыка |
| `skills/` | навык: отсюда берутся тексты гайда |
| `plugin.json`, `mcp.json`, `.claude-plugin/`, `.agents/plugins/`, `gemini-extension.json` | описания плагина для приложений: навык и MCP-сервер вместе. Списки плагинов (`marketplace.json`) в репозитории указывают на ветку `plugin`, где лежит собранный пакет |
| `scripts/build.mjs` | сборка: CLI одним файлом, библиотека, типы TypeScript, лицензии встроенных пакетов |

## Операции

У каждой операции есть ID, эффект (`read`, `write`, `execute`) и схема аргументов. Основные операции — `runtime.query`, `objects.get`, `objects.create`, `objects.patch`, `objects.delete`, `schema.get`, `schema.types`, `execute.script`, `rpc.call`, `logs.*`, `files.*`, `results.*`. Остальные — прямые вызовы API сервера: `native.*`, `web.*`.

Новая возможность — это определение операции в файле её семейства в `src/operations/` (шаги большой операции — в свой модуль, как у объектов и файлов); затем она получает тонкие обёртки в SDK, CLI и MCP-сервере. Тип ответа метода SDK компилятор сверяет с типом, который возвращает обработчик. Если у операции нет отдельного инструмента MCP, она доступна через `hcm_api_list` и `hcm_api_read`, `hcm_api_write`, `hcm_api_execute`. Так число инструментов и объём их описаний в контексте агента не растут.

## Ответ

```json
{ "ok": true, "data": {}, "meta": { "operationId": "…", "connection": "…", "durationMs": 12 } }
```

- Ответ больше `outputLimitBytes` сохраняется в `runtimeDir`; в `meta` приходят `truncated` и `resultId`.
- При ошибке: `error.code`, `error.message`, `error.hint`, для записи — `error.mutationOutcome`. Тексты ошибок пишутся один раз, под `HcmRuntime.call`, и называют операции по ID; CLI и MCP-сервер подставляют вместо ID свои имена (`src/frontend-names.ts`).
- Если сервер закрыл сессию после простоя (HTTP 401), клиент открывает её заново и один раз повторяет запрос.
- Тексты ошибок сервера обрезаются, пароль и пути сервера из них убираются.

## Что видит агент

Текста, который агент получает ещё до первого вызова, намеренно мало:

| Слой | Что | Когда попадает в контекст |
| --- | --- | --- |
| 0 | инструкции MCP-сервера и описания 23 инструментов; справка `wtctl help` | всегда |
| 1 | обзор гайда: `hcm_guide` без аргументов или `SKILL.md` навыка | когда агент берётся за задачу с сервером |
| 2 | темы гайда (`hcm_guide` с `topic`, файлы `references` навыка), `hcm_api_list`, `hcm_api_describe`, `wtctl help КОМАНДА` | по запросу агента |
| 3 | эта документация | для людей |

Примеры в описаниях инструментов и в навыке — вызовы, выполненные на настоящем сервере.

## Проверки

```shell
npm run verify
```

`npm run verify` проверяет форматирование и типы, сверяет тексты гайда с навыком, собирает проект, запускает тесты, проверяет ссылки и имена инструментов в документации и состав пакета. Тестам сервер не нужен: его ответы в них заданы заранее.

# Совместимость

Клиент делает те же вызовы, что и админка, поэтому его поведение зависит от версии сервера и от базы данных. Проверенные версии, базы и приложения перечислены в [README](../README.md#совместимость). Здесь собрано то, что на них отличается, что не работает и что не проверялось. Остальное на проверенных серверах ведёт себя одинаково.

Что именно не проходит на конкретном сервере, показывает `wtctl check`.

## Отличается между версиями и базами

- **Поиск на MS SQL и PostgreSQL.** Равенство строк на MS SQL не различает регистр, на PostgreSQL различает. Дату строкой в кавычках MS SQL принимает, PostgreSQL отвергает. Поле со списком значений сравнивается с ID и проверяется на пустоту по-разному. Поиск по условиям в JSON (`hcm_query` с `catalog` и `where`) эти различия сглаживает; в тексте XQuery их учитывает автор запроса. Подробно — в [гайде по запросам](../skills/wtctl/references/queries.md).
- **Удаление объекта на 2025.2.** На PostgreSQL после удаления остаются строки связанных каталогов: строки удалённой группы в `group_collaborators`, строки сотрудника и должности в `person_hierarchys`. На MS SQL после перезапуска сервера и после получаса без сохранений сервер отвечает на удаление без ошибки, а объект остаётся: `objects.delete` с `catalog` сообщает `READ_BACK_MISMATCH`, удаление проходит после сохранения любого документа.
- **Файловая база.** Неверный запрос даёт HTTP 500, а не пустой ответ; условие «не пусто» находит все строки; порядок строк и сортировка другие; дат в строках каталога нет. Поиск под файловую базу не подгонялся.
- **Запись `capabilityMask`** в `server info`: на MS SQL десятичная, на PostgreSQL шестнадцатеричная. Значение `database` от этого не зависит, см. [server.md](server.md#сведения-о-сервере).
- **Папки сервера.** Списки папок данных и папок кода у версий разные: на 2025.2.1535 в них на три папки больше, чем на 2025.1. Клиент берёт списки с подключённого сервера: `server info` → `dataFolders`, `codeFolders`.
- **Папка `storage`** читается через `files.read` на 2025.1 и не читается на 2025.2.
- **Функции библиотек.** Для вызова с клиента объявлено 253 функции на 2025.1.1171, 256 на 2025.1.1333, 257 на 2025.2. `rpc list` читает список с подключённого сервера.
- **`tools.eval_code_page_url`** на 2025.1.1171 выполняет код, начиная с 2025.1.1333 — заглушка.

## Не работает ни на одном проверенном сервере

- **Запись и удаление файла в папке кода вызовом, которым пишет админка.** Сервер принимает его только в папках данных. `files.write` и `files.delete` в папке кода работают кодом на сервере и требуют оба права, см. [security.md](security.md#права-подключения).
- **Удаление файла и папки в `wt_data` и `trash`.** Сервер отвечает на удаление как на успешное, а файл остаётся: `files.delete` там отказывает до отправки (`FILE_NOT_DELETABLE`). Эти папки сервер читает через память, поэтому после перезаписи файла `files.read` может отдать прежнее содержимое. Проверено на 2025.1.1333 — 2025.2.1535.
- **Чтение `x-local://Logs/…` и файлов из корня установки** через `files.read`. Логи читают команды `logs`.
- **Список папки штатной функцией** `tools.read_directory_server`: `Prohibited by security policy`. Список даёт `files.list`.
- **`native.lds.getModObjects` и `native.lds.getCatalogsStat`** отвечают пустым значением при любых аргументах.
- **Функции `tools.load_url_text_server` и `tools.load_url_data_server`** файл отдают, но теряют `\r` и портят текст UTF-8 без метки порядка байтов. Точно читает `files.read`.

## Не проверено

- Сервер под Linux; клиент под Linux и macOS.
- Версии сервера старше 2025.1 и новее 2025.2.1535.
- Адрес `https://`, reverse proxy, вход через SSO.
- Базы Oracle и Azure SQL: клиент только распознаёт их по флагам сервера.
- На файловой базе — всё, кроме самопроверки, файлов и кода на сервере.
- Учётная запись без доступа в админку.
- Сервер с изменёнными списками папок и сервер в кластере.
- Файл в папке кода больше 750 КБ текста или 580 КБ двоичных данных: это ограничение клиента.
- Большие поля объектов по адресу `x-db-obj://`: операций для них в клиенте нет.
- Агенты сервера на C#, агенты выгрузки и импорта.
- Каталоги на сотни тысяч записей, длинные очереди фоновых задач.
- Из операций, которые показывает `wtctl api list`: `releaseCursor` и `getCompoundResource` (курсора и составного ресурса на проверенных серверах не нашлось), остановка ещё идущей фоновой задачи через `killAsyncMethod`, результат `clearUploadChunks`, `web.experimental.authenticate`. Запись проверялась на 2025.1.1333 — 2025.2.1535.

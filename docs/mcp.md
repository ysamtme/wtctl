# Инструменты MCP

MCP-сервер `wtctl` запускается командой `wtctl mcp`. Как его установить — в [installation.md](installation.md).

Инструментов 23. Их описания занимают в контексте агента около 19 тысяч знаков. Подробности агент берёт по мере надобности из гайда (`hcm_guide`) и из `hcm_api_list`.

## Инструменты

| Инструмент | Что делает | Право |
| --- | --- | --- |
| `hcm_guide` | гайд: обзор и темы; к серверу не обращается | — |
| `hcm_status` | версия сервера, база данных и права подключения | — |
| `hcm_check` | проверка подключения по шагам | — |
| `hcm_types` | типы объектов и их каталоги | — |
| `hcm_schema` | поля типа, включая настраиваемые | — |
| `hcm_query` | поиск в каталоге по условиям | — |
| `hcm_object_get` | чтение документа объекта | — |
| `hcm_object_create` | создание объекта | `write` |
| `hcm_object_patch` | правка полей с предпросмотром | `write` |
| `hcm_object_delete` | удаление объекта | `write` |
| `hcm_script` | код на сервере (SP-XML Script) | `execute` |
| `hcm_xquery` | запрос XQuery целиком | `execute` |
| `hcm_logs_list`, `hcm_logs_search`, `hcm_logs_read`, `hcm_logs_follow` | логи сервера | — |
| `hcm_result_read`, `hcm_result_export` | большой сохранённый результат | — |
| `hcm_api_list`, `hcm_api_describe` | карта остальных операций и аргументы одной операции | — |
| `hcm_api_read`, `hcm_api_write`, `hcm_api_execute` | вызов операции по ID | по операции |

## Обычный порядок работы

Запись вида `hcm_types {search:"сотрудник"}` — сокращение: имя инструмента и его аргументы, не точный JSON.

1. `hcm_types {search:"сотрудник"}` — тип `collaborator`, каталог `collaborators`.
2. `hcm_schema {type:"collaborator", search:"логин"}` — поля.
3. `hcm_query {catalog:"collaborators", where:{is_dismiss:false}, fields:["id","fullname"]}` — объекты.
4. `hcm_object_get {id:"0x5555555555555501"}` — документ.
5. `hcm_object_patch {id, patch:{…}, preview:true}` — изменения без записи; тот же вызов без `preview` записывает.

## Ответ

Ответ инструмента — один блок текста с JSON:

```json
{
  "ok": true,
  "data": {
    "items": [{ "id": "0x5555555555555501", "fullname": "Иванов Иван Иванович" }],
    "total": 1
  },
  "meta": { "operationId": "runtime.query", "connection": "test", "durationMs": 12 }
}
```

При ошибке:

```json
{
  "ok": false,
  "error": {
    "code": "UNKNOWN_CATALOG",
    "message": "На сервере нет каталога collaborator.",
    "hint": "Похожие: collaborators. Каталоги и их типы объектов показывает hcm_types."
  },
  "meta": {…}
}
```

- ID объекта всегда строка: `"0x5555555555555501"`.
- Значения полей приходят строками: логические — `"1"` и `"0"`. Пустых полей в ответе нет; запрошенное поле, которого у типа или каталога нет, названо в `unknownFields`.
- Повторяемый элемент документа — всегда список, даже из одного элемента.
- Даты — местное время сервера, без смещения: `2026-10-02T16:42:00`.
- В текстах ошибок операции называются именами инструментов: `hcm_types`, а не `schema.types`.
- У операций записи в ответе есть `mutationOutcome`: `confirmed`, `not_sent` или `indeterminate`. Что с ним делать — в [security.md](security.md).

## Большой ответ

Ответ больше `outputLimitBytes` (по умолчанию 24 КБ) сохраняется на том компьютере, где запущен MCP-сервер. Как хранятся сохранённые результаты, описано в [configuration.md](configuration.md#сохранённые-результаты). Особенности MCP-сервера:

- Вместо данных приходят `meta.truncated` и `meta.resultId`, начало данных — в `data.preview`.
- `hcm_result_read` дочитывает результат частями: список ответа (`items`, `types`, `fields`) читается по элементам, остальное — текстом. Сервер HCM при этом второй раз не вызывается.
- `hcm_result_export` сохраняет результат в файл целиком: с `format:"jsonl"` — по строке на элемент списка, с `format:"text"` — текст лога или файла.
- Ответы короче, если задать `fields` в `hcm_query` и `hcm_object_get`.

## Остальные операции

- `hcm_api_list` без аргументов возвращает карту тем: функции библиотек, фоновые задачи, агенты сервера (объекты HCM, которые выполняют код по расписанию или по запуску), файлы, документ как XML, изменения, сведения о сервере, формы. С `topic` или `query` — операции с описаниями.
- Ещё две темы — основные операции и прямые вызовы протокола — в карте показаны только числом операций.
- `hcm_api_describe` показывает аргументы одной операции.
- Вызывается операция через `hcm_api_read`, `hcm_api_write` или `hcm_api_execute` — по её эффекту. Если инструмент выбран не тот, ответ называет нужный.

```json
{"operationId":"rpc.call","args":{"library":"tools","method":"get_version","arguments":["wtv"]}}
```

Несколько операций одним вызовом выполняет операция `runtime.batch`, см. [cli-sdk.md](../skills/wtctl/references/cli-sdk.md). Инструмент выбирается по шагу, которому нужно больше прав: чтение, запись, выполнение кода. Пакет из одних чтений идёт через `hcm_api_read`.

## Сессия на сервере HCM

MCP-сервер держит сессию на сервере HCM открытой, пока работает. Сервер HCM закрывает сессию после 15 минут простоя (измерено на версиях 2025.1.1171 и 2025.2.1535) и отвечает на следующий запрос HTTP 401. Тогда клиент сам входит заново и повторяет запрос. `PLATFORM_AUTH` агент видит, только если сервер не пустил при самом входе.

## Гайд по задачам

Агент читает гайд инструментом `hcm_guide`: без аргументов — порядок работы и список тем, с `topic` — одна тема. Ответ — текст, а не JSON. Человеку тот же текст печатает `wtctl guide ТЕМА`. Тема `cli-sdk` заканчивается разделом «На этом компьютере»: пути к Node.js, файлу CLI и SDK и способ взять то же подключение.

Тексты гайда лежат в навыке — это один источник и для агента, и для человека. Темы гайда перечислены в [README.md](../README.md#документация).

# Инструменты MCP

MCP-сервер `wtctl` запускается командой `wtctl mcp`. Как его установить — в [installation.md](installation.md).

MCP-сервер предоставляет 23 инструмента, их описания занимают в контексте агента около 19 тысяч знаков. Остальные подробности агент запрашивает по мере необходимости через встроенный гайд (`hcm_guide`) и `hcm_api_list`.

## Инструменты

| Инструмент | Что делает | Право |
| --- | --- | --- |
| `hcm_guide` | гайд: обзор и темы; к серверу не обращается | — |
| `hcm_status` | версия сервера, база данных и права подключения | — |
| `hcm_check` | проверка подключения по шагам | — |
| `hcm_types` | типы объектов и их каталоги | — |
| `hcm_schema` | поля типа, включая настраиваемые | — |
| `hcm_query` | поиск в каталоге по условиям | — |
| `hcm_object_get` | чтение документа объекта | — |
| `hcm_object_create` | создание объекта | `write` |
| `hcm_object_patch` | правка полей с предпросмотром | `write` |
| `hcm_object_delete` | удаление объекта | `write` |
| `hcm_script` | код на сервере (SP-XML Script) | `execute` |
| `hcm_xquery` | запрос XQuery целиком | `execute` |
| `hcm_logs_list`, `hcm_logs_search`, `hcm_logs_read`, `hcm_logs_follow` | логи сервера | — |
| `hcm_result_read`, `hcm_result_export` | большой сохранённый результат (`export` пишет файл на диск; право `write` не нужно) | — |
| `hcm_api_list`, `hcm_api_describe` | карта остальных операций и аргументы одной операции | — |
| `hcm_api_read`, `hcm_api_write`, `hcm_api_execute` | вызов операции по ID | по операции |

## Обычный порядок работы

Запись вида `hcm_types {search:"сотрудник"}` — сокращение для имени инструмента и его аргументов, а не точный JSON.

1. `hcm_types {search:"сотрудник"}` — находит тип `collaborator` и каталог `collaborators`.
2. `hcm_schema {type:"collaborator", search:"логин"}` — возвращает поля типа.
3. `hcm_query {catalog:"collaborators", where:{is_dismiss:false}, fields:["id","fullname"]}` — находит нужные объекты.
4. `hcm_object_get {id:"0x5555555555555501"}` — читает документ объекта.
5. `hcm_object_patch {id, patch:{…}, preview:true}` — показывает предпросмотр изменений без записи; повторный вызов без `preview` сохраняет правки.

## Ответ

Ответ инструмента — один блок текста с JSON:

```json
{
  "ok": true,
  "data": {
    "items": [{ "id": "0x5555555555555501", "fullname": "Иванов Иван Иванович" }],
    "total": 1
  },
  "meta": { "operationId": "runtime.query", "connection": "test", "durationMs": 12 }
}
```

При ошибке:

```json
{
  "ok": false,
  "error": {
    "code": "UNKNOWN_CATALOG",
    "message": "На сервере нет каталога collaborator.",
    "hint": "Похожие: collaborators. Каталоги и их типы объектов показывает hcm_types."
  },
  "meta": {…}
}
```

- ID объекта всегда строка: в ответе — `"0x5555555555555501"`, на входе годится и десятичная запись `"6148914691236517121"`.
- Значения полей приходят строками: логические — `"1"` и `"0"`. В `hcm_query` запрошенное пустое поле приходит пустой строкой `""` (или `[]` для списка). В `hcm_object_get` пустых полей в `data.data` нет: их имена названы в `emptyFields`, а вычисляемые поля каталога приходят в `fromCatalog`. Поле, которого нет у типа или каталога, названо в `unknownFields`.
- Повторяемый элемент документа — всегда список, даже из одного элемента.
- Даты — местное время сервера, без смещения: `2026-10-02T16:42:00`.
- В текстах ошибок операции называются именами инструментов: `hcm_types`, а не `schema.types`.
- У операций записи в ответе есть `mutationOutcome`: `confirmed`, `not_sent` или `indeterminate`. Что с ним делать — в [security.md](security.md).

## Большой ответ

Ответ больше `outputLimitBytes` (по умолчанию 24 КБ) сохраняется на том компьютере, где запущен MCP-сервер. Как хранятся сохранённые результаты, описано в [configuration.md](configuration.md#сохранённые-результаты). Особенности MCP-сервера:

- Вместо данных приходят `meta.truncated` и `meta.resultId`, начало данных — в `data.preview`.
- `hcm_result_read` дочитывает результат частями: список ответа (`items`, `types`, `fields`, `results`) читается по элементам, остальное — текстом. Сервер HCM при этом второй раз не вызывается.
- `hcm_result_export` сохраняет результат в файл целиком: с `format:"jsonl"` — по строке на элемент списка, с `format:"text"` — текст лога или файла.
- Ответы короче, если задать `fields` в `hcm_query` и `hcm_object_get`.

## Остальные операции

- `hcm_api_list` без аргументов возвращает карту тем: функции библиотек, фоновые задачи, агенты сервера, файлы, документ как XML, сведения о сервере, формы. С `topic` или `query` — операции с описаниями.
- Ещё две темы — основные операции и прямые вызовы протокола — в карте показаны только числом операций.
- `hcm_api_describe` показывает аргументы одной операции.
- Вызывается операция через `hcm_api_read`, `hcm_api_write` или `hcm_api_execute` — по её эффекту. Операции, которые сохраняют файл на локальный диск (`files.read` с `file` и `results.export`), идут через `hcm_api_write`, но права `write` на сервере не требуют. Если инструмент выбран не тот, ответ называет нужный.

```json
{"operationId":"rpc.call","args":{"library":"tools","method":"get_version","arguments":["wtv"]}}
```

Несколько операций одним вызовом выполняет операция `runtime.batch`, см. [cli-sdk.md](../skills/wtctl/references/cli-sdk.md). Инструмент выбирается по самому сильному шагу: только чтение — `hcm_api_read`, есть запись на сервер или на диск (`files.read` с `file`, `results.export`) — `hcm_api_write`, есть выполнение кода или вызов функции — `hcm_api_execute`.

## Сессия на сервере HCM

MCP-сервер держит сессию на сервере HCM открытой, пока работает. Сервер HCM закрывает сессию после 15 минут простоя (измерено на версиях 2025.1.1171 и 2025.2.1535) и отвечает на следующий запрос HTTP 401. Тогда клиент сам входит заново и повторяет запрос. `PLATFORM_AUTH` агент видит, только если сервер не пустил при самом входе.

## Встроенный гайд

Агент читает встроенный гайд инструментом `hcm_guide`: без аргументов возвращаются обзор и список тем, с параметром `topic` — выбранная тема. Ответ приходит текстом, а не в JSON. В терминале тот же текст печатает `wtctl guide ТЕМА`. Тема `cli-sdk` заканчивается разделом «На этом компьютере» — с путями к Node.js, файлу CLI и SDK, а также способом использовать то же подключение.

Тексты гайда хранятся в навыке — это единый источник для агента и для человека. Темы гайда перечислены в [README.md](../README.md#документация).

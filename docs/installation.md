# Установка

Первый шаг общий для CLI, SDK и MCP-сервера — настройка подключения к серверу HCM. На сам сервер ничего ставить не нужно.

После настройки подключения CLI и SDK уже готовы к работе. Для подключения к LLM-агентам добавляется шаг с установкой MCP-сервера — плагином (вместе с навыком, основной способ для Claude Code и Codex) или напрямую в конфиге приложения.

## Что нужно

- Node.js 22.16 или новее (версию покажет `node --version`). Для MCP-приложений команды `node` и `npx` должны быть в `PATH`, с которым запускается приложение.
- Учётная запись с доступом в админку сервера HCM.
- git — если планируется устанавливать плагин в Claude Code или Codex (через него приложения скачивают плагин).

## Шаг 1. Подключение к серверу HCM

```shell
npx -y wtctl config init
```

`npx` скачивает пакет `wtctl` из npm и запускает его CLI без предварительной установки. Команда спросит адрес сервера, логин и пароль и сохранит конфигурацию в `~/.wtctl/connections.json` (в Windows это `C:\Users\ИМЯ\.wtctl\connections.json`). Этот файл текущего пользователя используют CLI, SDK и MCP-сервер из любой папки.

Новое подключение создаётся только с правом на чтение. Включение записи и выполнения кода, добавление второго сервера и неинтерактивное создание подключения описаны в [configuration.md](configuration.md#создание-подключения).

По умолчанию пароль сохраняется в файле открытым текстом. Вместо этого его можно держать в переменной окружения, указав в файле только её имя: `--password-env WTCTL_PASSWORD`. В таком случае переменная должна быть доступна и процессу MCP-сервера. Codex передаёт MCP-серверам только явно перечисленные переменные, поэтому при установке плагина в Codex пароль хранится в файле.

Проверка подключения:

```shell
npx -y wtctl check
```

`check` последовательно проверяет вход, версию сервера, тестовый запрос, чтение документа, поля типа, библиотеки, логи и доступность портала, ничего не записывая на сервер. Если какой-то шаг не пройдёт, в ответе будет причина; частые ошибки разобраны в разделе [Если не получилось](#если-не-получилось).

## CLI и SDK

После проверки подключения CLI и SDK уже готовы к работе.

Для короткой команды `wtctl` в терминале пакет устанавливается глобально (без глобальной установки те же команды запускаются через `npx -y wtctl`; в остальной документации используется короткая запись, подробнее — в [cli.md](cli.md), а настройка редактора, автодополнения и кодировки Windows PowerShell 5.1 — в [Настройке терминала](cli.md#настройка-терминала)):

```shell
npm install -g wtctl
```

Для использования SDK пакет добавляется в проект:

```shell
npm install wtctl
```

После установки доступен `import … from "wtctl"`, а локальный CLI запускается как `npx wtctl`. У пакета нет сторонних зависимостей для запуска; подробнее — в [sdk.md](sdk.md).

## Шаг 2. Установка MCP-сервера в приложение

Доступны три варианта установки — выбирать нужно один из них.

| Приложение | Вариант |
| --- | --- |
| Claude Code, Codex | А. Плагин |
| Antigravity | Б. Плагин (из локальной папки) или В. [Только MCP-сервер](#antigravity) |
| Cursor, VS Code с Copilot, Copilot CLI | Б. Плагин (не проверено) |
| opencode | В. Только MCP-сервер, [с выключенным Code Mode](#opencode) |
| Любое приложение с поддержкой MCP | В. Только MCP-сервер |

Ставить одновременно плагин и отдельный MCP-сервер не следует — агент получит дублирующиеся инструменты и навыки. Если MCP-сервер `wtctl` уже добавлен в конфиг вручную или навык `wtctl` скопирован в отдельную папку (`~/.claude/skills/wtctl`, `~/.agents/skills/wtctl`), перед установкой плагина их стоит убрать.

### Вариант А. Плагин в Claude Code и Codex

Claude Code:

```shell
claude plugin marketplace add ysamtme/wtctl
claude plugin install wtctl@wtctl
```

Codex:

```shell
codex plugin marketplace add ysamtme/wtctl
codex plugin add wtctl@wtctl
```

Первая команда регистрирует репозиторий как источник плагинов с именем `wtctl`, вторая устанавливает и включает собранный плагин (в нём идут сразу MCP-сервер и навык).

В Claude Code плагин ставится на уровне пользователя — он станет доступен в терминале, десктопном приложении и расширении VS Code. Внутри сеанса Claude Code те же команды вводятся через слэш: `/plugin marketplace add ysamtme/wtctl` и `/plugin install wtctl@wtctl`.

В обоих приложениях навык из плагина имеет имя `wtctl:wtctl`.

#### Только в нужных проектах

Навык и описания инструментов MCP-сервера занимают часть контекста в каждом сеансе, даже там, где `wtctl` не используется. При желании плагин можно включать выборочно — только в нужных проектах.

**Claude Code.** Из папки нужного проекта выполняется:

```shell
claude plugin install wtctl@wtctl --scope local
```

Настройка сохраняется в `.claude/settings.local.json` и не попадает в git; в остальных папках плагин выключен. Если плагин уже установлен глобально для пользователя, его можно отключить на уровне пользователя и включить локально в нужных проектах:

```shell
claude plugin disable wtctl@wtctl --scope user
claude plugin enable wtctl@wtctl --scope local
```

`--scope local` действует только в основной папке репозитория и не распространяется на его worktree. Для worktree и общей настройки команды подходит `--scope project`: запись сохраняется в `.claude/settings.json` и коммитится в репозиторий. После клонирования каждому участнику достаточно один раз выполнить `claude plugin marketplace add ysamtme/wtctl` и `claude plugin install wtctl@wtctl --scope project`.

**Codex.** Плагин устанавливается обычным способом и отключается глобально в `~/.codex/config.toml`:

```toml
[plugins."wtctl@wtctl"]
enabled = false
```

В `.codex/config.toml` нужного проекта добавляется та же секция с `enabled = true`. Конфиг проекта Codex читает только для доверенных проектов. При повторном запуске `codex plugin add` (так выполняется обновление) значение в `~/.codex/config.toml` сбрасывается обратно в `true`, поэтому после обновления строку нужно вернуть.

### Вариант Б. Плагин в других приложениях

В собранном пакете есть манифесты плагина по открытому стандарту Agent Plugins 1.0 (`plugin.json`, `mcp.json`, `skills/`) и `mcp_config.json` для Antigravity. Для установки понадобится локальная [папка пакета](#установка-из-папки):

| Приложение | Как подключить папку |
| --- | --- |
| Antigravity | Выполнить `agy plugin install ПАПКА` — плагин копируется в `~/.gemini/config/plugins/wtctl` и становится доступен в App, IDE и CLI (проверено на `agy` 1.5.12). Для одного проекта папку можно скопировать в `<проект>/.agents/plugins/wtctl`. |
| Cursor | Скопировать папку в `~/.cursor/plugins/local/wtctl` (символические ссылки на другую папку Cursor пропускает; не проверено). |
| VS Code с Copilot | Добавить путь в настройку `chat.pluginLocations`: `{"ПАПКА": true}` (не проверено). |
| Copilot CLI | Выполнить `copilot plugin install ПАПКА` (не проверено). |

В Antigravity плагин регистрирует навык `wtctl:wtctl` и MCP-сервер `wtctl_wtctl` — если ранее `wtctl` был добавлен вручную в `mcp_config.json`, ручную запись стоит удалить, чтобы инструменты не дублировались.

<details>
<summary>Выборочное включение по проектам</summary>

- **Antigravity:** отключить глобальный плагин командой `agy plugin disable wtctl`, а для нужного проекта скопировать папку пакета в `<проект>/.agents/plugins/wtctl`.
- **VS Code с Copilot (не проверено):** в разделе Extensions → Agent Plugins - Installed выбрать Disable, затем в нужном проекте — Enable (Workspace). Настройка `chat.pluginLocations` работает только на уровне пользователя, в `.vscode/settings.json` проекта она не читается.
- **Copilot CLI (не проверено):** отключить через `copilot plugin disable wtctl`, затем добавить `enabledPlugins` в `.github/copilot/settings.json` (общий для репозитория) или `.github/copilot/settings.local.json` (личный). На один сеанс плагин подключается флагом `copilot --plugin-dir=ПАПКА`.
- **Cursor (не проверено):** встроенного включения по проектам для `~/.cursor/plugins/local` нет. Плагин можно подключать динамически через hook `workspaceOpen`, который получает папки проекта и возвращает пути к плагинам ([документация Cursor](https://cursor.com/docs/hooks)).

</details>

### Вариант В. Только MCP-сервер

MCP-сервер добавляется в конфигурацию приложения:

```json
{
  "mcpServers": {
    "wtctl": {
      "command": "npx",
      "args": ["-y", "wtctl", "mcp"]
    }
  }
}
```

В Claude Code и Codex эту запись можно добавить командой:

```shell
claude mcp add --scope user wtctl -- npx -y wtctl mcp
```

```shell
codex mcp add wtctl -- npx -y wtctl mcp
```

При запуске через `npx` старт занимает около секунды, так как `npx` обращается к npm. Если пакет установлен глобально (`npm install -g wtctl`), в конфиге достаточно указать `"command": "wtctl", "args": ["mcp"]` — тогда сеть при старте не требуется.

В этом варианте навык не ставится автоматически, но гайд доступен через инструмент `hcm_guide`. При желании папку [skills/wtctl](../skills/wtctl/SKILL.md) можно скопировать в папку навыков приложения вручную.

#### Antigravity

Глобально (для Antigravity App, IDE и CLI `agy`) MCP-сервер добавляется командой:

```shell
agy mcp add wtctl -- npx -y wtctl mcp
```

Команда дописывает запись в `~/.gemini/config/mcp_config.json` (в Windows — `C:\Users\ИМЯ\.gemini\config\mcp_config.json`). Для одного проекта тот же блок `mcpServers` (без поля `"type": "stdio"`, которое Antigravity игнорирует с предупреждением) можно положить в `<проект>/.agents/mcp_config.json`.

По умолчанию Antigravity загружает инструменты MCP по мере необходимости, поэтому при установке без плагина полезно скопировать папку навыка [skills/wtctl](../skills/wtctl/SKILL.md) в `~/.gemini/config/skills/wtctl` или `<проект>/.agents/skills/wtctl`.

Внешние оболочки, запускающие Antigravity через `agy acp`, могут использовать собственную папку конфигурации вместо `~/.gemini/config/`. В таких оболочках MCP-сервер и навык настраиваются в их собственном профиле либо через проектный `<проект>/.agents/`.

#### opencode

Запись добавляется в `~/.config/opencode/opencode.json` (в Windows — `C:\Users\ИМЯ\.config\opencode\opencode.json`) либо в `opencode.json` в папке конкретного проекта:

```json
{
  "mcp": {
    "servers": {
      "wtctl": {
        "type": "local",
        "command": ["npx", "-y", "wtctl", "mcp"],
        "codemode": false
      }
    }
  }
}
```

Команда `opencode mcp add --global wtctl -- npx -y wtctl mcp` создаёт ту же запись, но без поля `codemode` — его нужно дописать вручную (без `--global` конфиг пишется в `opencode.json` текущей папки).

Параметр `"codemode": false` отключает Code Mode, включённый в opencode по умолчанию. В Code Mode (проверено на opencode 2.0.29) модель вызывает инструменты через JS-код в инструменте `execute`, видит только часть инструментов с обрезанными примерно до 120 знаков описаниями и получает ошибки в виде исключений с JSON в тексте. С выключенным Code Mode инструменты доступны напрямую с именами `wtctl_hcm_*`.

## Шаг 3. Проверка MCP-сервера

- **Claude Code:** `claude mcp list` — в списке должен появиться MCP-сервер со статусом `Connected` (при установке плагином он называется `plugin:wtctl:wtctl`).
- **Codex:** `codex mcp list` — в списке должен быть `wtctl` (саму работоспособность запуска эта команда не проверяет).
- **Antigravity:** `agy plugin list` (при установке плагином — должны отображаться `1 skill, 1 MCP server`) или `agy mcp list` (при ручной записи в `mcp_config.json`).
- **opencode:** `opencode mcp list` — в списке должно быть `wtctl  connected`. Первый вызов сразу после старта фонового сервиса opencode может ответить `No MCP servers configured`; повторный запуск покажет актуальный список.

После этого в новом сеансе достаточно вызвать инструмент `hcm_status` — в ответе должны прийти версия сервера HCM и права текущего подключения.

MCP-сервер умеет стартовать и до настройки подключения: в этом случае инструменты сообщают, каких параметров не хватает, и подсказывают готовую команду для терминала. Пока подключение не найдено, конфиг перечитывается при каждом вызове, поэтому после `config init` перезапускать приложение не требуется.

## Если не получилось

Если инструментов `hcm_*` нет среди доступных:

- плагин и новый MCP-сервер становятся доступны в новом сеансе — уже открытые сеансы их не увидят;
- проверить запуск в Claude Code можно командой `claude mcp list`; если сервер не стартует, стоит проверить `node --version` в том же окружении, откуда запускается приложение (нужен Node.js 22.16+ и `node` / `npx` в `PATH`);
- если инструменты дублируются, в приложении подключены одновременно и плагин, и отдельный MCP-сервер — один из них нужно удалить.

Если инструменты или команды CLI возвращают ошибку, причину указывает код ошибки (`Ошибка [КОД]` в терминале, `error.code` в JSON):

| Ответ | Что это значит |
| --- | --- |
| `NOT_CONFIGURED` | подключение не настроено: нужен `wtctl config init` или переменные `WTCTL_URL`, `WTCTL_USERNAME`, `WTCTL_PASSWORD` |
| `PLATFORM_HTTP`, «Сервер … не отвечает» | детали указаны в `message` (отказ соединения, DNS, сертификат, таймаут); стоит проверить адрес и доступность сервера HCM |
| `PLATFORM_AUTH` | сервер HCM отклонил вход: неверный логин или пароль, либо у учётной записи нет доступа в админку |
| `UNKNOWN_CONNECTION` | подключения с таким именем в файле нет; в `message` указано, откуда взято имя, а в `hint` — список доступных подключений |
| `WRITE_DISABLED`, `EXECUTE_DISABLED` | у подключения выключено нужное право — см. [настройки прав](configuration.md#права) |

Путь к файлу подключений (для команд `config`) показывает `wtctl config path` (если задана `WTCTL_URL`, рабочие команды могут читать подключение из переменных окружения), а конкретный проблемный шаг — `wtctl check`.

## Другое подключение

Один экземпляр MCP-сервера работает с одним подключением; сервер из плагина использует подключение по умолчанию.

Чтобы подключить второй сервер HCM, в конфиг приложения добавляется ещё один MCP-сервер под другим именем (например, `wtctl-prod`). Имя подключения передаётся перед подкомандой `mcp`: `npx -y wtctl --connection prod mcp`.

На боевом сервере права `write` и `execute` стоит включать только при необходимости.

### Подключение для одного проекта

**Codex.** В `.codex/config.toml` доверенного проекта добавляется MCP-сервер с тем же именем `wtctl` — внутри этого проекта он переопределит сервер из плагина:

```toml
[mcp_servers.wtctl]
command = "npx"
args = ["-y", "wtctl", "--connection", "prod", "mcp"]
```

**Claude Code.** Из папки проекта выполняется:

```shell
claude mcp add --scope project wtctl-prod -- npx -y wtctl --connection prod mcp
```

Запись сохраняется в `.mcp.json` проекта. При первом запуске `claude` в этой папке потребуется подтвердить использование проектного MCP-сервера (до подтверждения `claude mcp list` показывает статус `Pending approval`). Сервер из плагина при этом не переопределяется даже при совпадении имени — в Claude Code он называется `plugin:wtctl:wtctl`, поэтому в проекте будут активны оба, и проектному серверу лучше дать отдельное понятное имя.

## Без файла подключений

Подключение для MCP-сервера можно передать через его переменные окружения — сам сервер при этом добавляется по варианту В:

```shell
claude mcp add --scope user wtctl --env WTCTL_URL=http://localhost:8088 --env WTCTL_USERNAME=user1 --env WTCTL_PASSWORD=… -- npx -y wtctl mcp
```

```shell
codex mcp add wtctl --env WTCTL_URL=http://localhost:8088 --env WTCTL_USERNAME=user1 --env WTCTL_PASSWORD=… -- npx -y wtctl mcp
```

Права включаются переменными `WTCTL_ALLOW_WRITE=true` и `WTCTL_ALLOW_EXECUTE=true`.

При таком способе пароль попадает в конфиг приложения и историю команд терминала. Кроме того, CLI и скрипты на SDK эти переменные не видят — им потребуется файл подключений либо те же переменные в собственном окружении.

## Встроенный гайд

Инструкции по работе с инструментарием клиента, примеры вызовов и разбор ошибок встроены в пакет:

- `hcm_guide` без аргументов возвращает обзор и список тем;
- `hcm_guide {topic:"queries"}` возвращает выбранную тему;
- в терминале тот же текст печатает `wtctl guide`.

Тема `cli-sdk` завершается разделом «На этом компьютере» с путями к Node.js, файлу CLI, точке входа SDK и способом использовать то же подключение, что у MCP-сервера. Это позволяет запускать CLI и писать скрипты на SDK, даже если `wtctl` не добавлен в `PATH`.

В составе плагина тот же текст подключается как навык — агент подгружает его автоматически при работе с сервером HCM.

## Обновление

Список изменений в версиях публикуется в [CHANGELOG](../CHANGELOG.md).

**Claude Code:**

```shell
claude plugin update wtctl@wtctl
```

Новая версия станет доступна в новом сеансе. Автообновление включается командой `/plugin` (вкладка Marketplaces → `wtctl` → Enable auto-update).

**Codex:** плагин обновляется повторным запуском `codex plugin add wtctl@wtctl` (Codex хранит локальную копию и не обновляет её автоматически). В Windows перед обновлением нужно закрыть активные сеансы Codex, иначе файлы работающего MCP-сервера будут заняты.

**Antigravity:** после `git -C ПАПКА pull` плагин обновляется повторным запуском `agy plugin install ПАПКА` (заменяет установленную копию).

**Пакет из npm:** глобальная установка обновляется через `npm install -g wtctl@latest`; `npx` скачивает актуальную версию автоматически.

## Удаление

- Плагин в Claude Code:

  ```shell
  claude plugin uninstall wtctl@wtctl
  claude plugin marketplace remove wtctl
  ```

  Если плагин ставился с `--scope local` или `--scope project`, удаление выполняется из папки проекта с тем же флагом `--scope`.

- Плагин в Codex:

  ```shell
  codex plugin remove wtctl@wtctl
  codex plugin marketplace remove wtctl
  ```

- Плагин в Antigravity: `agy plugin uninstall wtctl`.
- Глобальный пакет npm (если устанавливался): `npm uninstall -g wtctl`.
- При полной очистке можно удалить папку `~/.wtctl`, где хранятся файл подключений и сохранённые большие ответы.

## Установка из архива пакета

Архив `wtctl-X.Y.Z.tgz` (собирается командой `npm pack`) устанавливается так же, как пакет из npm — по пути к файлу:

```shell
npm install -g ./wtctl-X.Y.Z.tgz
```

После этого всё работает так же, как при обычной глобальной установке: команда `wtctl` и MCP-сервер `"command": "wtctl", "args": ["mcp"]`. Можно обойтись и без установки, распаковав архив (`tar -xzf wtctl-X.Y.Z.tgz`) в папку `package`: тогда CLI запускается через `node package/dist/cli/bin.js`, а MCP-сервер — через `"command": "node", "args": ["ПОЛНЫЙ_ПУТЬ/package/dist/cli/bin.js", "mcp"]`.

## Установка из папки

Запасной вариант без npm (а также для приложений, которым плагин передаётся локальной папкой). Собранный пакет хранится в ветке `plugin`:

```shell
git clone --branch plugin https://github.com/ysamtme/wtctl.git ПАПКА
```

Здесь `ПАПКА` — постоянный абсолютный путь: приложения запускают MCP-сервер напрямую из неё. Внешних зависимостей у сборки нет, `npm install` не требуется.

- **CLI:** `node ПАПКА/dist/cli/bin.js` (например, `node ПАПКА/dist/cli/bin.js config init`).
- **Плагин:** `claude plugin marketplace add ПАПКА` и `codex plugin marketplace add ПАПКА`, далее по шагам варианта А (Claude Code читает плагин прямо из этой папки); для Antigravity — `agy plugin install ПАПКА`.
- **Только MCP-сервер:** `"command": "node", "args": ["ПАПКА/dist/cli/bin.js", "mcp"]` (в JSON обратные слэши в путях Windows нужно экранировать: `C:\\tools\\wtctl\\dist\\cli\\bin.js`).
- **SDK:** `npm install ПАПКА` в нужном проекте.
- **Обновление:** `git -C ПАПКА pull`, затем новый сеанс в Claude Code, повторный `codex plugin add wtctl@wtctl` в Codex или повторный `agy plugin install ПАПКА` в Antigravity.
